# 实验流程记录、报警与常显状态需求

## 1. 文档定位

本文记录实验流程记录、数据处理、报警处理和常显状态展示的用户需求。目前处于需求讨论阶段，不表示功能已经实现、实现方案已经确定或设备已经验证。

实验日志模块的详细字段、统计结果、UI 映射、导出初稿以及与报警模块的职责边界，以独立章节[《实验日志模块需求与报警边界》](logging-module-requirements.md)为准；本文只保留跨模块总体需求。

需求来源：2026-07-27 用户讨论。

### 1.1 术语

- “批次”：保留给用户针对某个工件建立和管理的业务批次。本文不重新定义批次，也不要求实验流程记录或报警日志展示实验所属批次；
- “基础实验名称”：开始一组重复实验前确定的名称，不含重复序号；
- “实验名称”：一次实际执行使用的名称，格式为“基础实验名称-重复序号”；
- “重复实验”：由“重复次数”控制的一次实际执行；
- “实验流程记录”：每次实际实验完成、失败或停止后形成的结构化最终记录；
- “报警日志”：当前 UI 中的“报警记录”，用于管理故障或异常的触发、确认和恢复；
- “诊断日志”：软件写入文件的 Qt 日志，用于开发和维护诊断，不直接作为实验流程记录或报警日志展示给普通用户。

### 1.2 已确认的命名与关联规则

1. 不使用“实验批次”表示一次点击“开始”后执行的内容；需要整体描述时，使用“一组重复实验”；
2. 每次重复实验都形成独立的实验名称；基础实验名称为 `T-003`、重复次数为 3 时，三次实验名称依次为 `T-003-1`、`T-003-2`、`T-003-3`；
3. 即使重复次数为 1，实验名称仍使用 `T-003-1` 的形式，确保命名规则一致；
4. 实验流程记录始终关联具体实验名称；报警日志发生在具体实验期间时关联实验名称，两者均不增加批次字段；
5. 实验外发生的报警可以用 `--` 表示无关联实验；实验流程记录不存在无关联实验的情况；
6. 基础实验名称由当前配置中的 `motorModel` 和 `specimenId` 拼接生成，不增加单独的实验名称输入字段。

## 2. 总体目标

1. 用户能够按实验名称追溯每次重复实验的信息和结果；
2. 用户能够按位置区间生成统计结果，而不是默认统计全部采样数据；
3. 每次实际实验结束后形成实验流程记录，设备故障和需要处理的异常进入报警日志；
4. 机器运行期间的故障能够统一进入报警处理；
5. 常显状态区域能够及时反映故障，并与报警页面形成清晰交互；
6. 第一阶段遵循最小满足需求原则，不引入批次关联、通用日志分析等无关能力。

## 3. 实验记录与结果导出需求

### 3.1 重复执行

1. 用户通过“重复次数”设置一次点击“开始”后需要执行的实验次数；
2. 系统应按设置的重复次数依次执行，并为每次执行生成带序号的实验名称；
3. 每完成一次重复实验，系统应形成一条对应的实验记录；
4. 实验失败或被停止时，也应保留能够说明实际结果和原因的记录，不得表现为正常完成；
5. 实验记录无需保存或展示所属批次。

### 3.2 单次实验记录

每条实验记录至少应让用户识别：

- 实验名称；
- 当前重复序号和计划重复总数；
- 只需记录结束时间；
- 完成、失败或停止状态；
- 本次实验产生的结果；
- 失败或停止原因；
- 结果所使用的统计位置区间。

用户应能够在实验记录页面选中一条记录并导出该次实验的结果和对应实验数据。

### 3.3 重复实验汇总

一组重复实验结束后，系统应提供汇总结果，但不把该汇总命名为“实验批次”。汇总至少应反映：

- 基础实验名称；
- 计划重复次数；
- 实际完成、失败或停止的次数；
- 各实验名称及对应结果；
- 最终汇总结果；
- 整体完成、失败或停止状态。

即使重复实验未全部正常完成，已经产生的有效记录仍应允许查看和导出。

### 3.4 实验结果 Excel 导出初稿

1. 导出文件采用 Excel 可打开的工作簿形式；
2. 单次实验导出文件名暂定为 `实验名称_yyyyMMdd_HHmmss.xlsx`；
3. 单次实验工作簿暂定只包含一个 `实验数据` 标签页，顶部显示实验信息和实验结果，下方保存原始采样数据；
4. 汇总导出文件名暂定为 `基础实验名称_汇总_yyyyMMdd_HHmmss.xlsx`；
5. 汇总工作簿暂定包含 `汇总结果`、`实验列表`，并为每次重复实验提供对应内容；
6. 字段顺序、单位、标签页名称和大数据量处理方式由用户在此初稿上继续修改确认。

## 4. 位置区间统计需求

1. 用户生成实验结果时，应能够按照位置区间选择参与统计的数据；
2. 系统只对处于指定位置区间内的有效采样数据进行统计，不应默认使用全部实验数据；
3. 统计结果应明确显示所使用的位置起点、位置终点和有效数据量；
4. 指定区间内没有有效数据时，系统应明确提示结果无法生成，不得以零值或历史结果代替；
5. 每次实验结果和最终汇总结果均应能够追溯到其统计区间；
6. 统计区间是否直接使用现有采集起止位置，仍需讨论确认。

统计指标的最终清单、区间边界是否包含端点、运动方向处理和异常采样剔除规则仍需讨论确认。

## 5. 实验流程记录需求

1. 不再监视登录、自检、参数操作、设备连接变化、模式切换和报警确认等通用运行事件；
2. 每次实际实验完成、失败或停止时，只形成一条最终实验流程记录；
3. 记录只要求保存结束时间，并关联具体实验名称；
4. 数据库保存完整实验参数上下文、统计区间、有效采样数、统计结果和数据引用；
5. 复用现有运行记录页面，列表只显示结束时间、操作员、状态摘要和实验名称；
6. 工作台现有结果卡片分别显示四项单次结果和两项汇总结果；
7. 页面查询已落库的实验流程记录，不滚动监视实验中间状态；
8. 导出与实验结果导出合并，按选中的实验名称导出信息、结果和实验数据，不单独导出运行事件。

详细字段和 UI 映射以[《实验日志模块需求与报警边界》](logging-module-requirements.md)为准。

## 6. 报警日志需求

### 6.1 进入报警日志的条件

以下信息进入报警日志：

- 安全链、驱动器、控制器通信或关键传感器发生异常；
- 异常需要操作员关注、确认或采取处理措施；
- 异常会阻止实验启动、导致实验降级或导致实验停止；
- 故障是否恢复需要持续跟踪。

参数输入校验失败、普通操作失败、一般流程提示和不需要持续跟踪的瞬时信息不进入报警日志；如需诊断，只进入 Qt 文件诊断日志。

### 6.2 报警日志字段

第一阶段采用当前报警记录 UI 已显示的字段：

| 字段 | 必填 | 内容和格式 |
|---|---:|---|
| 触发时间 | 是 | 报警首次触发时间，显示格式为 `yyyy-MM-dd HH:mm:ss` |
| 等级 | 是 | 第一阶段使用“提示”“预警”“故障” |
| 设备/传感器 | 是 | 报警来源，例如安全链、驱动器、电机温度或冷却水流量 |
| 报警内容 | 是 | 描述异常事实，不混入操作员处理过程 |
| 确认状态 | 是 | “未确认”或“已确认”；确认不表示故障恢复 |
| 恢复时间 | 否 | 故障实际恢复的时间；未恢复时显示 `--` |
| 实验名称 | 否 | 报警发生在具体实验期间时填写带重复序号的名称；非实验期间显示 `--` |

报警日志同样不增加批次字段。

### 6.3 报警状态与操作

1. 报警页面分为“当前报警”和“历史报警”；
2. 未恢复的报警属于当前报警，恢复后进入历史报警；
3. 确认状态与恢复状态相互独立：报警可以“已确认但未恢复”，也可以“已恢复但未确认”；
4. 用户确认报警时，只更新报警记录的确认状态，不形成实验流程记录；
5. 第一阶段不单独引入“关闭”状态。除非后续明确需要维护审核或处理单闭环，否则“关闭”与“恢复”功能重叠；
6. 导致实验无法继续的报警应关联具体实验名称，实验记录同时保留停止或失败原因；
7. 蜂鸣器和三色灯属于可选报警输出，不得替代急停、安全联锁或其他设备安全措施。

### 6.4 查询和展示

1. 支持在当前报警和历史报警之间切换；
2. 历史报警支持按等级、设备/传感器和状态筛选；
3. 默认按触发时间倒序显示；
4. 常显状态区域只显示当前未恢复数量、最高等级和报警入口，不重复展示完整历史列表。

### 6.5 报警日志导出

第一阶段不提供报警日志导出功能。

## 7. 实验流程记录与报警日志的职责划分

### 7.1 划分原则

- 实验流程记录回答“这次实验何时结束、结果和最终状态是什么”；
- 报警日志回答“什么异常在什么时候发生，是否确认，是否恢复”；
- 诊断日志回答“软件内部为什么出现该现象”，面向开发和维护人员。

### 7.2 交叉场景处理

| 场景 | 实验流程记录 | 报警日志 |
|---|---|---|
| 实验正常完成 | 保存最终状态和统计结果 | 不记录 |
| 用户主动停止实验 | 保存停止状态和原因 | 不记录 |
| 参数输入不合法且实验未形成 | 不形成记录 | 不记录 |
| 设备故障触发 | 仅在实验被终止时保存最终状态和简要原因 | 创建或更新报警记录 |
| 操作员确认报警 | 不记录 | 更新确认状态 |
| 设备故障恢复 | 不记录 | 写入恢复时间并转入历史 |
| 报警导致实验停止 | 保存失败或停止状态和原因 | 保留报警事实并关联同一实验名称 |
| 软件内部重试或调用栈信息 | 不记录 | 不记录，由诊断日志保存 |

### 7.3 避免重复的约束

1. 不把报警触发、确认和恢复复制成实验流程记录；
2. 不在实验流程记录中维护报警等级、确认状态或恢复时间；
3. 不在报警日志中记录与异常无关的普通操作和流程节点；
4. 不把诊断日志直接导入实验流程记录或报警日志；
5. 同一故障导致实验停止时，两类日志可以同时存在，但文本分别描述“报警事实”和“实验流程结果”；
6. 用户界面和导出只使用实验名称关联，内部记录可保留不可见的唯一编号以避免同名记录混淆。

## 8. 常显状态区域需求

1. 用户在主要操作页面应始终能够看到设备和实验的关键状态；
2. 发生故障或报警时，常显状态区域应及时显示异常状态、最高报警等级和当前未恢复报警数量；
3. 用户应能够从常显状态区域进入报警页面查看对应报警；
4. 对应设备恢复后，常显状态应反映实际恢复结果；
5. 报警被确认但故障尚未恢复时，常显状态不得显示为正常；
6. 常显区域只承担状态摘要和报警入口，不重复展示完整报警列表；
7. 常显状态区域最终位置需要结合现有界面进一步确认。

## 9. 异常流程约束

本需求与《实验流程错误恢复与界面状态设计》共同遵守以下约束：

1. 一次实验失败后，应保留对应实验记录；达到报警条件的故障同时保留报警日志；
2. 普通操作错误不得导致开始、停止和恢复入口同时永久不可用；
3. 错误发生后，界面应区分“正在清理”“可以重新开始”和“设备安全状态无法确认”；
4. 设备安全状态无法确认时，不得仅通过确认报警恢复开始操作；
5. 报警日志、实验流程记录和界面状态应反映同一事实，但各自承担不同用途；
6. 用户导出失败实验时，应能够看到已完成内容以及明确的失败或停止原因。

关联设计：[`test_execution_error_recovery_design.md`](../../docs/test_execution_error_recovery_design.md)。该设计当前为草稿且尚未实现、尚未验证。

## 10. 第一阶段最小可用范围

- 每次重复实验形成独立名称和实验记录；
- 实验记录和重复实验汇总可查询、可导出；
- 结果按位置区间统计；
- 现有运行记录页面改为查询已经落库的实验流程记录；
- 实验流程记录与报警日志按本需求划分，不重复保存报警生命周期；
- 常显状态区域能够提示当前报警并进入报警页面；
- 故障后实验流程记录、报警日志和错误恢复状态保持一致。

蜂鸣器、三色灯、独立报警关闭流程、自定义 Excel 模板和通用日志分析能力不属于第一阶段必需内容。

## 11. 初步验收方向

1. 基础实验名称为 `T-003`、重复次数为 3 时，可查询 `T-003-1`、`T-003-2`、`T-003-3` 三条实验记录；
2. 实验流程记录和报警日志只关联实验名称，不显示或导出批次；
3. 登录、自检、连接变化、参数操作和报警确认不会出现在实验流程记录页面；
4. 现有运行记录页面显示结束时间、操作员、状态摘要和实验名称；
5. 报警页面显示触发时间、等级、设备/传感器、报警内容、确认状态、恢复时间、实验名称七个字段，第一阶段不提供导出；
6. 参数校验失败不形成实验流程记录，也不产生报警；
7. 设备故障只在报警模块维护触发、确认和恢复，不在实验流程记录中复制生命周期；
8. 操作员确认报警后，只更新报警确认状态；
9. 报警导致实验停止时，报警日志与实验流程记录关联同一实验名称；
10. 确认报警不会把尚未恢复的设备错误显示为正常；
11. 更改位置区间后，结果只使用区间内的有效数据；
12. 区间无数据时明确提示结果无法生成。

## 12. 待讨论事项

1. 位置统计区间直接复用采集起止位置，还是由用户单独设置；
2. 某次重复实验失败后，是立即停止后续实验，还是允许继续；
3. 最终汇总结果采用所有成功实验的平均值，还是使用其他计算规则；
4. 实验未全部完成时，汇总记录的状态命名；
5. 实验结果导出的最终字段、单位及排列顺序；
6. 原始采样数据量较大时，导出的范围和数量限制；
7. 哪些数据库、采集、通信和数据处理错误必须形成用户报警；
8. 是否确有独立于“恢复”的报警关闭或维护审核流程；
9. 蜂鸣器和三色灯是否纳入后续阶段，以及是否需要静音、试灯和复位操作；
10. 常显状态区域最终位于左侧、右侧还是其他固定位置。
