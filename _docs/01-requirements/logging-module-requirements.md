# 实验日志模块需求与报警边界

## 1. 文档定位

本文是实验日志模块的独立需求章节，当前只关注：

- 每次实际实验结束后形成的实验流程记录；
- 一组重复实验结束后形成的汇总记录；
- 完整数据库字段与现有 UI 关键字段之间的映射；
- 实验记录和汇总记录的 Excel 导出；
- 实验日志模块与报警模块的职责边界。

本模块不再监视或保存登录、自检、参数操作、设备连接变化、模式切换、报警确认等通用运行事件。软件内部调试信息继续由 Qt 文件诊断日志保存，不进入实验日志数据库和实验记录 UI。

## 2. 记录范围和命名

### 2.1 记录类型

实验日志模块只包含两类业务记录：

1. “单次实验流程记录”：每完成、失败或停止一次实际实验形成一条；
2. “汇总记录”：一组重复实验全部结束或确定不再继续时形成一条。

实验执行过程中的中间状态用于驱动当前工作台，不单独形成可查询的运行事件时间线。数据库只保存最终实验流程事实、计算所需上下文和结果。

### 2.2 命名和关联

1. “批次”保留给用户针对某个工件建立的业务批次，实验日志不保存、展示、筛选或导出实验所属批次；
2. 基础实验名称由当前配置中的 `motorModel` 和 `specimenId` 拼接生成，不增加单独输入字段；
3. 每次实际实验名称采用“基础实验名称-重复序号”，例如 `T-003-1`；
4. 单次实验流程记录只使用具体实验名称进行用户可见关联；
5. 汇总记录使用基础实验名称，并列出包含的具体实验名称；
6. 不存在与具体实验无关的业务日志记录，因此不再使用实验名称为 `--` 的普通运行记录。

## 3. 单次实验流程记录

### 3.1 形成时机

1. 每次实际实验进入完成、失败或停止状态时，只形成一条最终流程记录；
2. 记录只要求保存结束时间，不要求保存开始时间或所有中间状态变化时间；
3. 记录成功写入数据库后，现有实验记录页面才能查询到该记录；
4. 后续重复实验不得覆盖已经形成的记录；
5. 失败或停止时仍保留已经确定的统计结果；没有有效结果的字段保持为空，不得用零值或上一条实验结果代替。

### 3.2 数据库完整字段

数据库记录的字段可以多于 UI 展示字段。单次实验流程记录至少保存：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 记录标识 | 是 | 数据库内部唯一标识，不要求显示给用户 |
| 实验名称 | 是 | 带重复序号，例如 `T-003-1` |
| 基础实验名称 | 是 | 不含重复序号，例如 `T-003` |
| 重复序号 | 是 | 当前为第几次实际实验，从 1 开始 |
| 计划重复次数 | 是 | 本组重复实验计划执行总次数 |
| 结束时间 | 是 | 完成、失败或停止时的时间，格式为 `yyyy-MM-dd HH:mm:ss` |

| 实验状态 | 是 | `完成`、`失败`或`停止` |
| 失败/停止原因 | 否 | 状态不是完成时必填 |
| 测试速度 | 是 | 本次实验用于计算涡流力系数的速度，单位为 m/s |
| 统计位置起点 | 否 | 本次结果使用的位置区间起点 |
| 统计位置终点 | 否 | 本次结果使用的位置区间终点 |

| 平均涡流力 | 否 | 单位 N |
| 涡流力系数 | 否 | 单位 N·s/m |
| 涡流力波动值 | 否 | 单位 N |
| 涡流力波动率 | 否 | 单位 % |
| 实验数据引用 | 否 | 用于定位该实验对应的原始采样数据，不在 UI 列表显示 |

数据库中的数值字段保存计算结果的有效精度，不按 UI 显示小数位提前舍入。

### 3.3 单次统计规则

以下四项与工作台“每次循环结果”区域一一对应：

| 字段 | 计算规则 |
|---|---|
| 平均涡流力 | 指定位置区间内有效涡流力样本的算术平均值 |
| 涡流力系数 | `平均涡流力 ÷ 测试速度` |
| 涡流力波动值 | 有效区间内最大涡流力减去最小涡流力 |
| 涡流力波动率 | `涡流力波动值 ÷ 平均涡流力 × 100%` |

约束：

1. 四项统计值必须来自同一实验名称和同一统计位置区间；
2. 测试速度必须使用本次实验实际采用的配置值，不得读取后续已修改的配置；
3. 测试速度为零或无效时，不生成涡流力系数；
4. 平均涡流力为零或无效时，不生成涡流力波动率；

5. 统计结果缺失时 UI 显示 `----`，数据库和 Excel 保持为空；
6. UI 与 Excel 的显示精度由一个只读全局精度配置统一控制，数据库仍保存未按显示位数截断的数值；
7. 只读全局精度配置的具体名称和各字段小数位数待实现阶段确定。

## 4. 重复实验汇总记录

### 4.1 形成时机

1. 计划的重复实验全部结束，或因失败、停止而确定不再继续时，形成一条汇总记录；
2. 汇总记录不称为“实验批次”，也不保存所属批次；
3. 汇总记录一经形成，不得因重新开始另一组实验而覆盖。

### 4.2 数据库完整字段

汇总记录与单次实验流程记录使用相同类型的名称、结束时间、操作员和状态字段，并至少保存：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 记录标识 | 是 | 数据库内部唯一标识 |
| 基础实验名称 | 是 | 例如 `T-003` |
| 结束时间 | 是 | 本组重复实验结束或确定终止的时间 |
| 操作员 | 是 | 启动该组重复实验的登录用户 |
| 汇总状态 | 是 | `完成`、`部分完成`、`失败`或`停止` |
| 计划重复次数 | 是 | 用户设置的重复次数 |
| 已形成记录数 | 是 | 实际已形成的单次实验流程记录数量 |
| 完成次数 | 是 | 状态为完成的单次实验数量 |
| 失败次数 | 是 | 状态为失败的单次实验数量 |
| 停止次数 | 是 | 状态为停止的单次实验数量 |
| 有效汇总次数 | 是 | 实际参与多次平均的单次实验数量 |
| 实验名称列表 | 是 | 按重复序号列出已形成记录的实验名称 |
| 未参与汇总说明 | 否 | 记录未参与汇总的实验名称及原因 |
| 多次平均涡流力 | 否 | 单位 N |
| 多次平均涡流力系数 | 否 | 单位 N·s/m |

### 4.3 汇总统计规则

| 字段 | 计算规则 |
|---|---|
| 多次平均涡流力 | 对有效参与记录的“平均涡流力”做算术平均 |
| 多次平均涡流力系数 | 对有效参与记录的“涡流力系数”做算术平均 |

初步参与规则：

1. 只有状态为完成且对应统计值有效的单次实验参与该项多次平均；
2. 失败、停止或统计值为空的记录不参与计算，但仍保留在汇总记录中；
3. 两项汇总指标的有效记录集合应保持一致；
4. 没有有效参与记录时，两项汇总统计值为空，不显示为零；
5. 是否允许人工排除已经完成的异常记录，仍需确认。

## 5. 现有 UI 绑定要求

### 5.1 工作台结果卡片

不新增实验结果监视页面，直接使用工作台已经存在的结果卡片：

| UI 区域 | 显示字段 | 更新时间 |
|---|---|---|
| 每次循环结果 | 平均涡流力、涡流力系数、涡流力波动值、涡流力波动率 | 每次实际实验结果确定后更新 |
| 最终实验结果 | 多次平均涡流力、多次平均涡流力系数 | 汇总记录结果确定后更新 |

工作台卡片只显示当前一组重复实验的关键结果，不承担历史记录查询。下一组实验开始时可以清空为 `----`，已落库历史结果不受影响。

### 5.2 现有运行记录页面

复用现有 `RunRecordsPage` 作为历史实验流程记录列表，不再展示登录、自检、连接变化和普通操作事件。当前四列映射为：

| 现有 UI 列 | 数据来源 | 显示内容 |
|---|---|---|
| 时间 | 单次记录的结束时间 | `yyyy-MM-dd HH:mm:ss` |
| 操作员 | 单次记录的操作员 | 用户显示名称 |
| 操作内容 | 单次记录的状态和结果摘要 | 例如“实验完成”“实验失败：数据库写入失败”“实验停止：用户停止” |
| 关联实验 | 单次记录的实验名称 | 例如 `T-003-1` |

页面只显示操作员定位历史实验所需的关键字段。统计位置、有效采样数、测试速度、完整统计值、数据引用等字段保存在数据库和导出文件中，不全部展开成列表列。

### 5.3 查询和刷新

1. 日期筛选作用于实验结束时间；
2. 关键词至少搜索实验名称、操作员、状态和失败/停止原因；
3. 默认按结束时间倒序显示；
4. 页面查询已写入数据库的最终记录，不监视或滚动显示实验中间状态；
5. 每次实验记录成功落库后，可以刷新列表显示该条记录；
6. 不提供批次筛选条件。

## 6. Excel 导出格式初稿

### 6.1 单次实验记录导出

1. 复用现有运行记录页面的导出按钮位置，但导出对象改为用户选中的实验记录，不再导出通用运行事件筛选结果；
2. 文件名暂定为 `实验名称_yyyyMMdd_HHmmss.xlsx`；
3. 工作簿只使用一个 `实验数据` 标签页；
4. 标签页顶部显示实验名称、重复序号、计划重复次数、结束时间、操作员、状态、失败/停止原因、统计位置区间、有效采样数和四项统计结果；
5. 标题信息下方保存该次实验的原始采样数据；
6. UI 列表未显示的数据库字段可以进入导出文件；
7. 不包含批次信息，也不包含通用运行事件时间线。

### 6.2 汇总记录导出

1. 文件名暂定为 `基础实验名称_汇总_yyyyMMdd_HHmmss.xlsx`；
2. `汇总结果` 标签页保存汇总基本字段、两项多次平均和有效汇总次数；
3. `实验列表` 标签页每个实验名称一行，保存状态和四项单次统计结果；
4. 是否在汇总文件中继续包含每次实验的全部原始采样数据，待用户结合数据量确认；需要有效区间数据
5. 不包含批次信息和通用运行事件时间线。

导出数值使用只读全局精度配置格式化。以上标签页、字段排列和样式为初稿，由用户继续修改确认。

## 7. 实验日志与报警模块的职责边界

### 7.1 基本原则

- 实验日志模块回答“这次实验何时结束、结果是什么、最终状态是什么”；
- 报警模块回答“什么异常发生了、是否确认、是否恢复”；
- 实验日志不再记录报警确认、报警恢复或普通操作行为；
- 报警模块不计算或保存实验统计结果；
- 两个模块只使用具体实验名称表达用户可见关联，不引入批次关联；
- 第一阶段报警记录不提供 Excel 导出。

### 7.2 场景划分

| 场景 | 实验日志模块 | 报警模块 |
|---|---|---|
| 实验正常完成 | 保存完成状态和四项单次结果 | 不记录 |
| 多次实验完成 | 保存汇总状态和两项多次平均 | 不记录 |
| 实验结果偏离目标值 | 保存实际结果和判定 | 默认不报警 |
| 用户主动停止实验 | 保存停止状态和原因 | 不报警 |
| 参数或统计区间无效，实验未形成 | 不形成实验流程记录 | 不报警，可进入诊断日志 |
| 安全链、驱动器、通信或关键传感器故障 | 仅在实验被终止时保存失败状态和简要原因 | 创建或更新报警记录 |
| 报警导致实验失败或停止 | 保存最终实验状态和原因 | 保存报警事实及生命周期 |
| 操作员确认报警 | 不记录 | 更新确认状态 |
| 故障实际恢复 | 不记录 | 写入恢复时间并转入历史报警 |
| 软件内部调试信息 | 不记录 | 不记录，由诊断日志保存 |

### 7.3 边界约束

1. 平均涡流力、涡流力系数或波动率不满足实验目标，属于实验结果判定，不自动等同于设备报警；
2. 只有满足设备、通信、安全或传感器报警条件时，才由报警模块创建报警；
3. 统计区间无有效数据属于结果无法生成；只有其根因同时构成设备或系统故障时，根因才进入报警模块；
4. 报警导致实验结束时，实验日志保存最终状态和简要原因，报警模块保存完整报警内容、确认状态和恢复时间；
5. 不把报警触发、确认、恢复复制成实验日志记录；
6. 不在实验日志中维护报警等级、确认状态或恢复时间；
7. 不在报警记录中复制实验统计结果。

## 8. 第一阶段验收方向

1. 登录、自检、连接变化、参数操作和报警确认不会出现在实验流程记录列表；
2. 每次实际实验结束后，数据库只形成一条对应实验名称的最终流程记录；
3. 数据库保存完整记录字段，现有运行记录页面只显示结束时间、操作员、状态摘要和实验名称；
4. 工作台四张单次结果卡在每次实验结果确定后更新；
5. 工作台两张最终结果卡在汇总结果确定后更新；
6. 失败、停止或无有效数据时，不使用零值或历史结果冒充有效统计值；
7. 选择一条历史实验记录可以导出该实验的信息、结果和原始数据；
8. 报警页面仍独立维护触发、确认和恢复，第一阶段不提供报警导出；
9. 报警导致实验停止时，实验记录和报警记录通过同一实验名称分别追溯；
10. 所有实验记录、UI 和导出均不包含批次字段。

## 9. 待确认事项

1. 统计字段的只读全局精度配置名称及各字段小数位数；
2. 统计位置区间的单位和端点规则；
3. 多次平均是否只包含正常完成记录；
4. 是否允许人工排除某条已完成记录，以及所需权限和原因；
5. 汇总状态“部分完成”的业务定义；
6. 汇总导出是否包含每次实验的全部原始数据；
7. 数据库、采集和数据处理错误进入报警模块的具体分级规则。
